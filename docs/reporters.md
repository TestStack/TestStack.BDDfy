# Reporters

BDDfy generates human-readable reports from your test runs. Reports are produced at two levels:

- **Per-scenario processors** (`IProcessor`) — run after each scenario (e.g., console output)
- **Batch processors** (`IBatchProcessor`) — run once after all scenarios complete (e.g., HTML file)

## Console Reporter

Enabled by default. Prints each scenario to standard output immediately after it runs.

```
Story: Account holder withdraws cash
    As an account holder
    I want to withdraw cash from an ATM
    So that I can get money when the bank is closed

  Scenario: Account has insufficient fund
      Given the account balance is $10
        And the card is valid
      When the account holder requests $20
      Then the atm should not dispense any money        [Passed]
        And the atm should say there are insufficient funds [Passed]
```

### Disabling Console Output

```csharp
Configurator.Processors.ConsoleReport.Disable();
```

## HTML Reporter

Enabled by default. Produces a standalone HTML file (`bddfy-report.html`) in your output directory after all tests complete.

Features:
- Collapsible stories and scenarios
- Color-coded pass/fail/not-implemented status
- Duration display
- Example tables rendered inline

### Choosing a Report Style

BDDfy ships with three HTML report builders:

| Builder | Description |
|---------|-------------|
| `ModernReportBuilder` | Single-page app with embedded data (default) |
| `ClassicReportBuilder` | Traditional collapsible HTML with inline styles |
| `MetroReportBuilder` | Flat-design alternative with tile layout |

The `HtmlReport` batch processor uses `ModernReportBuilder` by default. Switch styles via the `Configure` method:

```csharp
// Use the Classic report builder
Configurator.BatchProcessors.Configure<HtmlReporter>(r =>
    r.Configuration.ReportBuilder = new ClassicReportBuilder());

// Use the Metro report builder
Configurator.BatchProcessors.Configure<HtmlReporter>(r =>
    r.Configuration.ReportBuilder = new MetroReportBuilder());
```

Or provide your own `IReportBuilder` implementation:

```csharp
public class MyHtmlBuilder : IReportBuilder
{
    public string CreateReport(FileReportModel model)
    {
        // Build your custom HTML from the model
        return "<html>...</html>";
    }
}

Configurator.BatchProcessors.Configure<HtmlReporter>(r =>
    r.Configuration.ReportBuilder = new MyHtmlBuilder());
```

### Configuration

```csharp
Configurator.BatchProcessors.HtmlReport.Disable();

// Or customize:
Configurator.BatchProcessors.Configure<HtmlReporter>(r =>
{
    r.Configuration.OutputFileName = "AcceptanceTests.html";
    r.Configuration.OutputPath = @"C:\Reports";
    r.Configuration.ReportHeader = "My Project";
    r.Configuration.ReportDescription = "Acceptance Tests";
    r.Configuration.ResolveJqueryFromCdn = false;
});
```

The `HtmlReportConfiguration` properties:

| Property | Default | Description |
|----------|---------|-------------|
| `OutputFileName` | `bddfy-report.html` | Name of the generated file |
| `OutputPath` | Test output directory | Where the file is written |
| `ReportHeader` | `BDDfy Report` | Title shown in the report |
| `ReportDescription` | `Report generated by TestStack.BDDfy` | Subtitle |
| `ReportBuilder` | `ModernReportBuilder` | The builder that generates HTML |
| `ResolveJqueryFromCdn` | `true` | Load jQuery from CDN vs embedded |
| `FileWriter` | `FileWriter` | Writes the output file |
| `FileReader` | `FileReader` | Reads custom CSS/JS overlays |

### Named HTML Reports

Use `htmlReportName` to generate multiple HTML files (one per name):

```csharp
this.BDDfy(htmlReportName: "ATM");
```

## Markdown Reporter

Produces a `BDDfy.md` file. Disabled by default.

```csharp
Configurator.BatchProcessors.MarkDownReport.Enable();
```

Example output:

```markdown
# Story: Account holder withdraws cash

As an account holder
I want to withdraw cash from an ATM
So that I can get money when the bank is closed

## Scenario: Account has insufficient fund

Given the account balance is $10
  And the card is valid
When the account holder requests $20
Then the atm should not dispense any money
  And the atm should say there are insufficient funds
```

## Text Reporter

The `TextReporter` is the base class used by `ConsoleReporter`. It formats scenarios as indented plain text with step results and example tables. You can subclass it for custom text output (e.g., writing to a file or test output).

```csharp
public class FileTextReporter : TextReporter
{
    protected override void Write(string text, params object[] args)
        => File.AppendAllText("report.txt", string.Format(text, args));

    protected override void WriteLine(string? text = null)
        => File.AppendAllText("report.txt", text + Environment.NewLine);

    protected override void WriteLine(string text, params object[] args)
        => File.AppendAllText("report.txt", string.Format(text, args) + Environment.NewLine);
}
```

Register it:

```csharp
Configurator.Processors.Add(() => new FileTextReporter());
```

## Diagnostics Reporter (JSON)

Produces a `bddfy-diagnostics.json` file with structured data about all stories, scenarios, and steps. Disabled by default.

```csharp
Configurator.BatchProcessors.DiagnosticsReport.Enable();
```

Useful for:
- CI/CD pipeline integration
- Custom dashboard consumption
- Test result analysis tools

## JSON Data File Reporter

Produces a data file containing all story and scenario data serialized as JSON. Disabled by default. Designed for building custom report frontends or feeding data into dashboards.

```csharp
Configurator.BatchProcessors.JsonDataFileReport.Enable();
```

### JavaScript Format (default)

By default, the reporter outputs a `.js` file (`bddfy-stories.js`) that assigns the JSON to a variable, ready for use in a browser:

```javascript
var STORIES_DATA = { "Stories": [...] }
```

This is ideal for custom single-page HTML reports that load the data via a `<script>` tag:

```html
<script src="bddfy-stories.js"></script>
<script>
  // STORIES_DATA is now available
  console.log(STORIES_DATA.Stories.length + " stories");
</script>
```

### Plain JSON Format

To output a plain `.json` file instead (for API consumption or CI tools), disable the default factory and add a custom instance:

```csharp
Configurator.BatchProcessors.JsonDataFileReport.Disable();
Configurator.BatchProcessors.Add(new JsonDataFileReporter(javascriptFormat: false));
```

This produces `bddfy-stories.json` with raw JSON content.

### Custom Output Location

```csharp
Configurator.BatchProcessors.JsonDataFileReport.Disable();
Configurator.BatchProcessors.Add(new JsonDataFileReporter(
    new ReportConfiguration("my-test-data.json") { OutputPath = @"C:\Reports" },
    javascriptFormat: false));
```

### Using with a Custom HTML Report

A common pattern is to combine the JSON data file with a custom HTML page:

1. Enable the JSON data file reporter in JavaScript mode
2. Create a custom HTML file that references the generated `.js` file
3. Use any frontend framework to render the data

```csharp
[ModuleInitializer]
public static void Initialize()
{
    // Disable the built-in HTML report
    Configurator.BatchProcessors.HtmlReport.Disable();

    // Enable JSON data output for your custom frontend
    Configurator.BatchProcessors.JsonDataFileReport.Enable();
}
```

## Enabling / Disabling Reporters

All batch reporters use a factory pattern with `Enable()` and `Disable()` methods:

```csharp
// Disable all built-in batch reports
Configurator.BatchProcessors.HtmlReport.Disable();
Configurator.BatchProcessors.MarkDownReport.Disable();
Configurator.BatchProcessors.DiagnosticsReport.Disable();
Configurator.BatchProcessors.JsonDataFileReport.Disable();

// Enable only Markdown
Configurator.BatchProcessors.MarkDownReport.Enable();
```

## Adding a Custom Batch Reporter

Implement `IBatchProcessor`:

```csharp
public class MyCustomReporter : IBatchProcessor
{
    public void Process(IEnumerable<Story> stories)
    {
        // Generate your report from the story/scenario/step data
    }
}

// Register it
Configurator.BatchProcessors.Add(new MyCustomReporter());
```

## Report Filtering with RunsOn

The `HtmlReportConfiguration.RunsOn(Story)` method lets you filter which stories appear in a report. Override it to split stories across multiple report files:

```csharp
public class AtmReportConfiguration : HtmlReportConfiguration
{
    public AtmReportConfiguration()
    {
        OutputFileName = "ATM.html";
    }

    public override bool RunsOn(Story story)
    {
        return story.Metadata?.Type.Namespace?.Contains("Atm") == true;
    }
}

// Use Configure to apply it
Configurator.BatchProcessors.Configure<HtmlReporter>(r =>
    r.Configuration = new AtmReportConfiguration());
```
